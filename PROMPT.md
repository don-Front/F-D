Проанализируй текущий starter template и внеси только перечисленные ниже улучшения.

Не изменяй существующую архитектуру, не переименовывай папки и не добавляй новые библиотеки, кроме тех, которые действительно необходимы.

Главная цель — довести starter template до стабильной версии 1.0.

---

# 1. package.json

Добавь раздел

"engines"

с минимальной поддерживаемой версией Node.js, соответствующей файлу `.nvmrc`.

Пример:

```json
"engines": {
  "node": ">=24"
}
```

Если раздел уже существует — не дублируй его.

---

# 2. GitHub Actions

Проанализируй текущий workflow.

Если сейчас выполняется только сборка, расширь его.

Workflow должен выполнять проверки в следующем порядке:

1. Checkout проекта
2. Setup Node.js (используя версию из .nvmrc или соответствующую LTS)
3. npm install
4. npm run lint
5. npm run build

Если любой этап завершается ошибкой — workflow должен завершиться ошибкой.

Никакого Deploy добавлять не нужно.

Workflow должен оставаться максимально простым и быстрым.

---

# 3. README.md

Полностью проверь README.

Убедись, что он соответствует текущему состоянию проекта.

README должен содержать:

- описание проекта;
- стек технологий;
- требования к Node.js;
- установку;
- запуск;
- сборку;
- описание структуры проекта;
- описание alias "@";
- краткое описание каждой основной папки;
- информацию о CI;
- информацию о Deploy через Vercel.

Если структура проекта изменилась — обнови дерево каталогов.

README должен выглядеть профессионально.

---

# 4. Финальная проверка

После всех изменений обязательно выполни:

npm install

npm run lint

npm run build

Исправь все найденные ошибки.

---

# 5. Финальный аудит

После завершения проведи аудит проекта.

Ответь на следующие вопросы:

1. Есть ли что-нибудь лишнее в starter template?

2. Есть ли что-нибудь устаревшее?

3. Есть ли что-нибудь, что противоречит современным best practices React + Vite?

4. Есть ли что-нибудь, что может создать проблемы через год использования?

5. Можно ли считать этот starter template стабильной версией 1.0 для создания десятков будущих проектов?

Если ответ "нет" — самостоятельно исправь найденные проблемы.

Если ответ "да" — объясни почему.

Не предлагай новые функции "на будущее".

Не усложняй архитектуру.

Цель — получить простой, чистый, профессиональный starter template, который можно использовать годами без постоянных изменений.
